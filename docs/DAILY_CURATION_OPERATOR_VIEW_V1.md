# Daily Curation Operator View V1

Daily Curation Operator View is the human-facing projection of Daily Curation Run.

It turns the structured `review / publishable / held` snapshot into a compact operator
workspace without adding write authority.

## Core boundary

```text
OPERATOR VIEW != VERIFICATION
OPERATOR VIEW != PUBLISH
OPERATOR VIEW != SEND
OPERATOR VIEW != APPLY
```

The view is read-only.

## Endpoint

`POST /api/v1/curation/daily/view`

The endpoint reuses the Daily Curation service and therefore inherits the same
verification hold and publication-gating semantics.

It supports:

- all Daily Curation queue/digest controls;
- digest renderer options;
- operator-view title;
- Markdown or plain-text operator rendering;
- checklist visibility;
- held-reason detail visibility.

## Human layout

The rendered view has three primary sections:

### Review ahora

Each review item shows:

- rank;
- title/company;
- operational priority;
- human-readable reason;
- next action;
- source URL;
- optional checklist;
- evidence-draft endpoint.

The structured response also preserves the exact immutable
`VerificationReviewCard` generated by Review Session.

This means a client can display a friendly card while retaining the exact payload needed
for the next read-only evidence-draft step.

### Publishable

The operator view embeds the already-rendered publishable Community Digest from Daily
Curation.

The operator does not need to reconstruct or re-rank the digest in the UI.

```text
publishable != published
```

The view does not send it anywhere.

### Held

The view shows:

- total held count;
- shown/omitted counts;
- human-readable verification reason counts;
- displayed held opportunity IDs.

Held remains a verification backlog, not a closed-opportunity list.

## Human-readable labels

Internal bounded reason/action/checklist codes are preserved in the underlying structured
models, while the operator projection translates them into readable Spanish labels.

Examples:

```text
DISCOVERY_ONLY_NEEDS_OFFICIAL_SOURCE
-> buscar fuente oficial

FIND_OFFICIAL_SOURCE
-> Buscar fuente oficial

CONFIRM_APPLICATION_ACTIONABLE
-> Confirmar vía de aplicación/acción
```

The translation changes presentation only. It does not modify policy or priority.

## Exact review-card preservation

Every operator review item contains:

- `card_sha256`;
- the exact `VerificationReviewCard`;
- `next_endpoint=/api/v1/availability/verification/draft`.

The operator projection never reconstructs or weakens card integrity.

The Evidence Draft layer still recomputes the card hash and independently checks stale
Availability Memory.

## Formats

V1 supports:

- `markdown`;
- `plain`.

HTML is intentionally not part of V1.

Keeping rendering text-first avoids introducing a frontend framework before the operator
workflow has been exercised in daily use.

A future web UI can consume the same structured view without moving domain logic into
the browser.

## Dependency boundary

The default operator view exists only when Daily Curation exists.

If Daily Curation is disabled or unavailable, the operator view returns unavailable
instead of rebuilding queue/digest rules itself.

## Profile independence

Operator View does not use:

- CandidateProfile;
- CAREER score;
- INCOME_NOW score;
- personal eligibility;
- personal tier.

It is a community curation workspace.

## Read-only behavior

Building the operator view does not:

- fetch external sources;
- record sightings;
- record verification;
- create evidence drafts;
- invoke verification confirm;
- mutate opportunity status;
- publish or send the digest;
- apply to opportunities.

The response exposes no external actions.

## Intended V1 workflow

```text
POST /api/v1/curation/daily/view
        |
        +-> Review cards
        |      |
        |      +-> human opens source
        |      +-> human records finding
        |      +-> POST /availability/verification/draft
        |
        +-> Publishable digest
        |      |
        |      +-> operator reviews/copies manually
        |
        +-> Held summary
```

This is the first V1 surface intended to act as the operator's daily workspace rather
than as an internal domain primitive.
